# 产品形态与定价体系（内部 v1）

> 回答三个问题：产品长什么样（形态）？价格体系怎么搭（不只是价格点，是定价的机器）？什么能最快落地、要不要做 App？
> 依据：[产品SKU与渠道战术](产品SKU与渠道战术.md) + [Sigma模式分析与定价返佣策略](Sigma模式分析与定价返佣策略.md) + 商业模式文档产品边界（明确不做三个原生 App 同时上线）。2026-08-06 初稿（梁嘉文）。

## 一、产品形态总纲：系统在后台，客户在聊天里

**核心判断：客户不需要一个新 App，客户需要「在他已经打开的软件里把货发了」。**

- 中资货主（EPZ 光伏、贸易商）活在**微信**里——今天他们发货就是在微信群里喊一嗓子；
- 本地货主、车队、司机活在 **WhatsApp** 里；
- 我们的做法不是把他们拉进我们的 App，而是**把 AI 数字员工派进他们的群**。

四端形态：

| 端 | 形态 | 承载什么 | 不做什么 |
|---|---|---|---|
| **货主端** | 微信群/WhatsApp 里的 AI 数字员工 + 下单小程序/H5 + 免登录追踪链接 | 询价、下单、状态推送、POD 电子回执、对账单 | 不强制注册、不做原生 App |
| **车队/司机端** | WhatsApp Bot + 轻量 PWA（接单确认、装货拍照、POD 上传、回款查询） | 派单、证据链、快付状态 | 不做原生 App（车队自有 GPS 接口拿轨迹，不依赖司机手机常驻定位） |
| **内部控制塔** | Web 后台（真正的系统核心） | 九环节状态机：订单/报价/调度/在途/异常/结算/利润账本/审计日志 | 这是自建交易内核的全部，也是唯一的「重」投入 |
| **公开层** | 官网 + 税费计算器 + 无坑问答 | 引流与信任建立 | — |

**类比**：拼多多早期长在微信里，快递查询长在短信/H5 里——**平台的本体是控制塔和数据，不是客户手机上的图标**。

## 二、要不要做 App：结论与升级路径

**结论：现在不做，未来按触发条件升级。**（与产品边界既有决策一致：首期 WhatsApp/PWA + 司机轻端；上一批玩家把种子钱花在 App 和下载量上，是六大失败教训之一。）

| 阶段 | 形态 | 升级触发条件 |
|---|---|---|
| M0–M2 | 微信/WhatsApp + AI 数字员工 + H5 追踪 | — |
| M2–M6 | + 下单小程序（微信）+ 司机 PWA | 首批运单跑通后 |
| M6–M12 | 小程序功能加深（授信额度、账单、发票） | 月运单 ≥200 |
| M12+ 评估 | 原生 App（司机端优先） | 仅当出现 PWA 解决不了的硬需求：司机常驻后台定位（车队 GPS 覆盖不足时）、离线场景、推送到达率瓶颈 |

## 三、快速落地排序：前 8 周能上什么

**原则：每一周都要有能给客户/投资人看的东西，每一个都为「首批已完成、已取证、贡献为正的运单」服务。**

| 周 | 上线什么 | 形态 | 依赖 |
|---|---|---|---|
| W1–W2 | **S1 试运行**：Sigma 现有订单走「微信群数字员工 + 结构化台账」——AI 转单、生成标准报价单（PDF/图片）、状态人肉+半自动推送 | 零开发产品化：报价单模板 + 数字员工 + 台账 | 报价单模板、价目表 v1 |
| W2–W3 | **K2 税费计算器**上线（挂官网+独立 H5）：HS 档位 + CIF 值 → 关税/IDF/RDL/VAT 明细 | H5 | 税率表（已研究入库） |
| W3–W6 | **控制塔 MVP v0**：订单-运单-状态-POD-对账五张表 + 审计日志；免登录追踪链接 H5 | Web 后台 + H5 | 全栈 ×1 + AI 编程 |
| W4–W6 | **K1 无坑问答**上线：微信/WhatsApp AI Bot + 支付（$99.9/年） | Bot | 陈德雷知识库梳理 |
| W6–W8 | **下单小程序 v0**（询价→报价→确认）+ S4 空运接单 | 小程序 | 控制塔 API |

到 W8 的完整故事：**客户在微信里 5 分钟拿到分段明细报价单，确认后全程有追踪链接，POD 电子回执，月底对账单自动出**——这就是「软件上线 + 真实交易数据」，正好接上沙利文场投资人的卡点。

## 四、定价体系：一台会报价的机器

定价体系 = 五层架构，不是一张价格表：

### 4.1 五层架构
| 层 | 内容 | 规则 |
|---|---|---|
| **1 · 挂牌价目** | 三档（框架/标准/散单）× 线路 × 柜型/车型 × 海空 | 锚定 Sigma 实测曲线（$2,100→$3,300 档位逻辑）；价目表版本化管理，改价留痕 |
| **2 · 附加费引擎** | 燃油联动（锚 110 KES/km，波动 ±10% 触发调整〔假设〕）、等待费（免费 X 小时后按小时）、旺季系数、危险品/超限、跨境系数 | 自动计算、报价单上分项列示 |
| **3 · 合同价管理** | 框架客户年约价 + 量阶梯返还（季度达量返服务费，不打单价） | 低于「最低可持续价」的合同必须销售+财务双签 |
| **4 · 报价流程** | 询价 → AI 生成分段明细报价单（清关段/干线段/附加费/税费实报实销代缴）→ **有效期 48h**（燃油与汇率波动敞口控制）→ 确认即锁价 | 低置信/低毛利自动升级人工；每张报价单入库，成交率反哺定价 |
| **5 · 支付与账期** | 散单：预付 100%；标准：30% 订金 + POD 结清；框架：预充值/月结（授信矩阵：额度×账期×保证金联动付款记录，逾期自动停单） | 税费代缴一律预付（负营运资金设计） |

### 4.2 报价单（对客户的定价界面）就是产品
一张标准报价单必须让客户看到四样东西——这是和市场黑箱报价的最直观差异：
1. **分段明细**：清关段 / 干线段 / 附加费，各是各的钱；
2. **税费实报实销**：预估税费 + 「以海关实际核定为准，单据全给你」；
3. **SLA 承诺**：准时到车、POD 时限、延误赔付条款印在报价单上；
4. **有效期与锁价规则**。

### 4.3 定价数据飞轮
每张报价单 → 成交/流失 + 原因标签 → 回流价目表与附加费参数 → 报价越来越准。**报价单数据库是定价引擎的训练集，从 W1 第一张报价单就开始积累。**

## 五、与经营模型的钩稽
- W1–W8 的全部投入已含在最小启动档预算内（技术月度 $2.5k + 全栈 2 人）；
- 报价中位时长 KPI：≤15 分钟（6 个月）→ ≤5 分钟（12 个月）；
- 首月目标：Sigma 存量订单 ≥50 单走系统出报价单与运单记录〔假设，8/15 与德雷定〕。
