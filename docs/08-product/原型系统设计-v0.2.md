# AFA 原型系统设计 v0.2

> 日期：2026-08-08
> 状态：基于 Sigma 一线流程、真实报价结构与组织配置重构；用于产品评审和现场访谈，不是开发需求冻结稿。

## 1. 本轮重构结论

旧原型把产品理解为“运营控制塔 + 客户查单”。最新一线材料表明，平台真正的交易内核是：

**客户、清关公司、车队三类参与方分别注册和履约，由平台把订单、货物、费用、凭证、责任和资金条件串成一单一档。**

清关公司和车队即使属于同一家公司，也必须拆为两个角色，因为两者的字段、承载量、结算条件和风险完全不同。

## 2. 产品地图

| 产品面 | 使用者 | 关键任务 |
|---|---|---|
| WhatsApp AI 助手 | 客户 | 清关咨询、查单、缺件提醒、费用解释、转人工、引导下单 |
| 客户 H5 | 客户 | 选择服务组合、订单列表、节点与 ETA、钱包、官方费用直付、单据、风险与评价 |
| 平台控制塔 | AFA 运营 | 跨角色异常、订单主数据、资金与责任、合作方承载量、早会与复盘 |
| 清关公司工作台 | 清关公司 | 资料预审、申报、查验、DO、放行、品类标签和承载量 |
| 车队工作台 | 车队/调度 | 车柜匹配、司机车牌、Booking、GPS、POD、还箱与结算条件 |
| 客服工作台 | AFA 客服 | 一个客户一个服务空间、问答转订单、人工升级、费用与延误解释 |
| 经营数据大屏 | 管理层 | 规模、时效、客户风险、运力、流程卡点、系统 ROI 与数据缺口 |

## 3. 三类订单

1. **纯运输**：客户已有清关能力，只采购车辆与运输履约；
2. **清关 + 运输一体**：默认形态，一个客户窗口，但清关与车队仍在后台分段履约和结算；
3. **纯清关**：客户使用自有车队，平台只管理清关流程与文件。

订单类型决定必填字段、节点启用范围、合作方匹配和付款计划，不是页面标签。

## 4. 订单主对象

| 对象 | 最小字段 |
|---|---|
| 订单 | 客户、服务组合、贸易条款、货物品类、EPZ 属性、起讫点、承诺范围 |
| 货物批次 | 提单、柜号/托数、CIF、HS 大类、预计到港、指定堆场 |
| 单据 | 箱单、发票、CO、CoC、ACD、BL、DO、税单、Booking、POD、还箱凭证 |
| 节点 | 状态、实际时间、下一节点 ETA、责任方、图片/视频、人工确认人 |
| 费用 | 发生节点、费用性质、收款方、付款方、官方凭证、责任归因、钱包扣款状态 |
| 异常 | 类型、触发条件、影响、责任方、证据、升级人、关闭结果 |
| 伙伴履约 | 清关公司/车队、能力标签、核定承载量、接受状态、SLA、结算条件 |
| 钱包与支付 | 充值、冻结、分段扣款、官方直付凭证、退款、多退少补 |
| Bond | 总额度、已占用、待释放、未来 7/14/30 天需求、续购生效时间 |

## 5. 真实九环节状态机

1. 发货前置：箱单、发票、CO、CoC、指定堆场、ACD；
2. 到港等泊：预计 2–5 天，异常最长可达一个月，主要用于通知；
3. 卸船与免箱期：卸船落地即启动倒计时；
4. 清关决策：码头直清或转堆场，默认 70–80% 走堆场；
5. 缴费与 DO：KPA、船东和官方税费优先由客户直付；
6. 车辆 Booking：放行柜数与预约车辆数必须一致；
7. 提柜与干线运输：GPS、节点打卡和下一节点 ETA；
8. 卸货与还空箱：POD、还箱凭证作为尾款释放条件；
9. Bond 释放：还箱后释放占用额度，并滚动预测未来缺口。

Bond 与主货流并行运行，但在产品上必须显示，因为其缺口会直接阻断清关。

## 6. 第一版异常枚举

等泊、未指定堆场、ACD 未申报、人工领取 DO、Bond 不足、开箱查验、滞箱滞港、车货不同步、罢工/系统宕机、柜区紧张。

异常必须是独立对象，不能只写在聊天备注里。每条异常都应绑定订单、节点、影响时间/金额、责任方与凭证。

## 7. 费用与资金规则

- 关税、VAT、KPA、船东、堆场等官方费用：实报实销、凭证可查，优先给客户官方账号直付；
- 客户钱包：一次审批充值，平台按节点分段扣款；
- 未确认异常费用：不得自动扣款；
- 快付、加油授信、订单融资：资金由持牌方承担，平台不做垫资；
- 还箱凭证未上传：车队尾款不可释放；
- 代付仅走可过 KYC/AML 的合规通道。

## 8. AI 与人工闸门

AI 可以提取聊天字段、检查缺件、草拟报价、解释已确认节点、总结异常与生成通知。

以下动作必须人工确认：报价发送、费用责任认定、钱包扣款、改单、合作方选择、清关建议、异常关闭、结算与放款。

## 9. MVP 收缩

### P0

- 订单主数据与一单一档；
- 九环节节点可视；
- 报价引擎 v1（EPZ / 非 EPZ、税费、CoC 开关、按目的地运价）；
- 放行柜数与车辆 Booking 对齐；
- WhatsApp 查询与客户 H5。

### P1

- Bond 台账与未来 7/14/30 天预警；
- 钱包、分段扣款与官方费用直付凭证；
- GPS、POD、还箱与尾款条件。

### P2

- 清关公司标签、历史承载量与双向预警；
- 评价体系；
- 持牌资金方的供应链金融入口。

## 10. 本轮 Demo 数据纪律

- `AFA-SIM-*` 均为匿名模拟订单；
- 1,020 柜、150 票、4,386 累计柜量、585+ 辆、价格和线路等来自首轮粗数；
- 卸船到工厂约 7.5 天、70–80% 转堆场、单车约 8 趟/月等来自 8/8 一线访谈，仍带待核属性；
- 今日放行/预约、Bond 缺口、钱包余额、合作方承载量等是为了验证交互而生成的模拟数据；
- 任何待核或模拟指标不得进入正式经营披露。
