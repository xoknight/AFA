## 1. 站点结构（dist/）

```
dist/
├── index.html                    对外官网 中文版（17KB，图片外链）
├── en/index.html                 对外官网 英文版（同模板 + 文案表渲染）
├── ir/fc67ec2cbfbd/index.html    融资页（中文单文件 642KB，noindex，隐蔽路径）
├── img/                          官网图片：6 张品牌效果图 + 12 个业务图标 + 反白 logo
├── 404.html                      品牌 404 页
├── robots.txt                    Allow / ，Disallow /ir/
├── sitemap.xml                   中英两个 URL，带 hreflang
├── _headers                      安全响应头 + /ir/* 强制 noindex + /img/* 长缓存
├── _redirects                    /index.htm、/home、/investors → /
├── favicon.png / favicon.ico / apple-touch-icon.png
└── og-image.png                  1200×630 分享卡片图（微信/LinkedIn）
```

源文件分工：

| 文件 | 作用 |
|---|---|
| `src/site_corporate.template.html` | 对外官网**版式**（中英共用一套，文案是 `{{TOKEN}}` 占位符） |
| `src/site_i18n.py` | 对外官网**中英文案表**——改文字只改这里 |
| `src/site_financing.template.html` | 融资页（单文件、图内嵌，仅中文） |
| `src/build_assets.py` | 从 VI 设计稿 PDF 提取官网图片 → `assets/site/`（VI 改版才需要跑） |
| `src/build_site.py` | 融资页模板 → 单文件 HTML |
| `src/build_dist.py` | 组装 `dist/`：渲染中英双语官网 + 灌 SEO/hreflang + 拷图 + 生成附属文件 |

改版流程（**唯一正确姿势**）：

```bash
# 1. 改文案 → src/site_i18n.py（中英两份都要改）；改版式 → site_corporate.template.html
#    不要直接改 dist/ 与 src/site_financing.html，它们是产物
# 2. 构建
python3 src/build_site.py && python3 src/build_dist.py
# 3. 提交推送 → Cloudflare 自动发布（约 30 秒）
git add -A && git commit -m "官网改版：xxx" && git push origin main
```

> 双语规则：中文在根路径 `/`，英文在 `/en/`，导航右上角与页脚各有一个切换入口；两页互相 `hreflang` 指认，`x-default` 指中文页。加第三种语言时在 `site_i18n.py` 加一份文案表、在 `build_dist.py` 的 `PATHS` 加一行即可，模板不用动。

> 融资页隐蔽路径 token 写在 `src/build_dist.py` 的 `IR_TOKEN`。**改掉它并重新部署 = 旧链接立即 404**，用于链接外泄后的作废。

## 2. 阿里云国际站：把 NS 改到 Cloudflare

先做第 3 步的前半段（在 Cloudflare 添加站点，拿到两个 NS 地址），再回来改。

1. 登录 alibabacloud.com → **Domains** → 找到 `afafreight.com` → **Manage**
2. **DNS Servers / DNS 服务器** → Modify → 选 **Custom DNS**（不要选阿里云 DNS）
3. 填入 Cloudflare 给的两条，例如 `xxx.ns.cloudflare.com` / `yyy.ns.cloudflare.com`（**以 Cloudflare 控制台实际显示为准**）
4. 保存。若提示域名被锁（Registrar Lock / 转移锁），先在同页 Unlock 一下再改 NS（改完可锁回）

生效：一般 10 分钟～2 小时，最长 48 小时。Cloudflare 会发邮件通知 "is now active"。

> **不需要**做域名转移（transfer），也**不需要**备案——网站不落地中国大陆服务器。

## 3. Cloudflare：建站点 + 建 Pages 项目

### 3.1 添加站点

1. dash.cloudflare.com → **Add a site** → 输入 `afafreight.com` → 选 **Free** 方案
2. Cloudflare 扫描完已有记录（阿里云那边一般是空的，忽略）→ **Continue**
3. 页面会给出两条 nameserver → 拿去做第 2 步

### 3.2 建 Pages 项目（连 GitHub）

1. 左栏 **Workers & Pages** → **Create** → **Pages** → **Connect to Git**
2. 授权 GitHub（选 **Only select repositories** → 只勾 `xoknight/AFA`，最小授权）
3. 选仓库 `xoknight/AFA` → **Begin setup**
4. 构建配置（**关键，照抄**）：

   | 字段 | 值 |
   |---|---|
   | Project name | `afafreight` |
   | Production branch | `main` |
   | Framework preset | **None** |
   | Build command | **留空** |
   | Build output directory | `dist` |
   | Root directory | 留空（仓库根） |

   > 站点是本地构建好提交的，Cloudflare 端不装 Python/Pillow，**务必留空 build command**，否则会构建失败。

5. **Save and Deploy** → 30 秒后拿到 `https://afafreight.pages.dev`，先自查一遍页面

### 3.3 绑定正式域名

> **新版控制台注意**：Cloudflare 已把 Pages 并入 Workers。项目建好后在控制台里显示为 **Worker**，默认地址是 `https://<项目名>.<账户名>.workers.dev`（本项目实际为 `https://afa.afafreight.workers.dev`），不是 `*.pages.dev`。功能一致，`_headers` / `_redirects` 照常生效。

入口按控制台版本二选一：

- **新版（Workers）**：Workers & Pages → 点项目 `afa` → **Settings** → **Domains & Routes** → **Add** → **Custom domain**
- **旧版（Pages）**：Pages 项目 → **Custom domains** → **Set up a custom domain**

依次添加两条：

1. `afafreight.com` ← **根域必须加，否则整站打不开**（www 的 301 也会指向一个不存在的地方）
2. `www.afafreight.com`
3. Cloudflare 自动写 DNS 记录并签证书，等状态变 **Active**（1–5 分钟）

### 3.4 www → 根域 301（**可选**，统一权重）

> **可以跳过**：首页 `<link rel="canonical">` 已指向 `https://afafreight.com/`，搜索引擎不会判重复内容。只要 §3.3 把 www 也加进 Pages 自定义域名，`www.afafreight.com` 就能正常打开，只是不会 301 到根域。想做得干净再配下面这条规则。

**找不到菜单？先确认站对了地方**——Redirect Rules 属于**域名（zone）**，不在 Workers & Pages 项目里：

`dash.cloudflare.com` → 左栏 **Websites / 账户首页域名列表** → 点 **afafreight.com** → 左栏 **Rules** → **Overview** → **Create rule** → **Redirect Rule**

直达链接：`https://dash.cloudflare.com/?to=/:account/:zone/rules/overview`（会让你先选账号和域名）

规则内容（新版 UI 用通配符，最省事）：

| 字段            | 填什么（**只填反引号里的内容，别把说明文字粘进去**）   |
| ------------- | ------------------------------ |
| Rule name     | `www to apex`                  |
| 匹配方式          | 选 Wildcard pattern             |
| Request URL   | `https://www.afafreight.com/*` |
| Target URL 类型 | 选 Wildcard pattern             |
| Target URL    | `https://afafreight.com/${1}`  |
| Status code   | 301，勾 Preserve query string    |

> ⚠️ **实际踩过的坑（2026-08-06）**：Target URL 被误填成从文档复制的整行（含 `**Wildcard pattern** →` 这类 markdown），结果 www 301 到一个相对路径，浏览器无限跳转报错。Target URL 框里**有且只有一个 URL**，不含空格、箭头、星号、反引号。改完用 `curl -sSI https://www.afafreight.com/` 看 `location:` 头验证。

三条备选路径（UI 版本不同时按顺序试）：

1. Rules → Overview → **Templates**，里面有现成的 “Redirect from WWW to Root”，点了自动填好
2. 老 UI 是 Rules 下直接有 **Redirect Rules** 子项，进去 Create rule；匹配条件用 `Hostname` `equals` `www.afafreight.com`，Then 选 **Dynamic**，表达式 `concat("https://afafreight.com", http.request.uri.path)`
3. 更老的 **Page Rules**（免费版 3 条）：URL 填 `www.afafreight.com/*` → 设置选 **Forwarding URL** → **301** → 目标 `https://afafreight.com/$1`

> 前提：域名状态必须已是 **Active**（NS 切换生效）。还在 “Pending nameservers” 时规则能建但不生效。

### 3.5 SSL / 安全（一次性开关）

SSL/TLS 页：

- 加密模式：**Full (strict)**
- Edge Certificates → **Always Use HTTPS** = 开
- **Automatic HTTPS Rewrites** = 开
- **Minimum TLS Version** = TLS 1.2
- HSTS：站点稳定跑一周后再开（开了短期内不可逆，别急）

Speed → Optimization：Brotli 默认开，其余保持默认（单文件 HTML 已经足够快）。

## 4. Cloudflare Email Routing（企业邮箱转发）

1. 控制台 → 域名 → 左栏 **Email** → **Email Routing** → **Get started**
2. Cloudflare 自动添加 3 条 MX（`route1/2/3.mx.cloudflare.net`）+ 1 条 SPF TXT → **Add records and enable**
3. **Destination addresses** → 添加并验证收件邮箱（如 `gavin.leung@lexoavatar.com`，去邮箱点验证链接）
4. **Routing rules** → 建转发地址：

   | 地址 | 转发到 | 用途 |
   |---|---|---|
   | `contact@afafreight.com` | Gavin | **官网页面上公示的地址** |
   | `info@afafreight.com` | Gavin | 通用询盘 |
   | `sales@afafreight.com` | Gavin（后续转销售） | 客户询价 |
   | `gavin@afafreight.com` | Gavin | 个人对外 |
   | Catch-all | Gavin | 兜底，防错拼丢件 |

### ⚠️ 三条注意

1. **只能收，不能发**。要以 `contact@afafreight.com` 身份发信，得另接发信服务：
   - 轻量：Gmail「以其他地址发送」+ 一个 SMTP 中继（如 Resend / Brevo 免费额度）
   - 正规：Google Workspace 或腾讯企业邮（约 ¥30–80/人/月）——**届时要把 MX 换成对方的，Email Routing 必须先关**，两者不能共存
2. 上线后尽快补 **DMARC**（TXT `_dmarc` → `v=DMARC1; p=none; rua=mailto:contact@afafreight.com`），避免域名被冒用发钓鱼邮件
3. 客户发的正式函件走转发后，回信地址会是你的私人邮箱——对外沟通建议尽早升级到真企业邮箱（列入 §8 待办）

## 5. 融资页的保护边界（口径明确，别误解）

采用的是**隐蔽路径 + noindex**，不是访问控制：

- ✅ 猜不到、搜不到、站内无链接、robots 禁爬、响应头强制 noindex
- ❌ **链接一旦转发出去，拿到的人就能看**——含估值、条款、财务预测、里程碑拨付

使用纪律：

1. 只点对点发给已签 NDA 或已进入实质沟通的投资人
2. 不发进群、不贴朋友圈、不放进任何公开文档
3. 怀疑外泄 → 改 `src/build_dist.py` 的 `IR_TOKEN` → 重新构建推送 → 旧链接立即失效
4. 需要真正的准入控制时（投资人数量上来后），升级 Cloudflare Zero Trust → Access，对 `/ir/*` 加邮箱一次性验证码，免费额度 50 人

另：Pages 会同时保留 `afafreight.pages.dev` 这个公开域名，同样能访问全部内容。已用 canonical 标签把权重指回正式域名、`/ir/*` 有 noindex 响应头兜底；不希望它存在的话，可在 Pages → Custom domains 里把访问收敛（付费版 Access 可覆盖 pages.dev）。
